01 / FOUNDATION

Jev 是什么？

Jev 是 TypeSafe 推出的旗舰模型，也是第一个 System One model。它不是 Agent Framework，不是 Orchestration Runtime，也不是可以下载源码逐行研究的开源模型。

它的接口非常克制：发送一个 state 和一组 questions，返回代码可以直接使用的 answers。没有自由文本生成，也没有从文本中解析结构的步骤。

截至本站研究日期 2026-11-25，文档列出的最新稳定版本为 jev-1.14.0，别名 jev-latest；API 版本 0.2.0（OpenAPI 3.1.0）。

02 / MODEL CLASS

System One 是什么？

System One 是一类为快速、结构化、软件可直接使用的判断而构建的模型。名字来自 Kahneman 的“快思考”：快速、聚焦、直觉式的小判断。

官方定义：System One 模型评估一个 state，返回 typed answers 和 probabilities；它们不写回复、不生成代码、不解释推理过程。

官方称 System One 针对 calibrated decisions 训练，概率会针对结果优化以反映不确定性。这是厂商声明，本站不将其等同于独立验证结论。

05 / JUDGMENT ENGINEERING

Atomic Judgment

复杂业务判断不应塞进一个巨大的 Choice。正确做法是把问题拆成多个范围清晰的原子问题，在同一次请求中并行、隔离评估，再用代码组合结果。

官方文档强调：一个问题的答案不会成为另一个问题的上下文；需要新判断时，不必担心它影响已经验证过的判断。

优先级变化时应改代码里的规则与权重，而不是重写 prompt。这正是“智能放在正确抽象层”的含义。

06 / SEPARATION

Judgment / Decision 分离

Judgment（Jev）

“用户是否想退款？”“这条消息是否包含威胁？”“政策是否支持退款？”——需要语义理解的小问题。

Logic（Code）

金额阈值、权限检查、状态机、例外规则。可精确计算的部分不应交给模型。

Decision（System）

自动退款、转人工、风控团队、继续执行。最终动作由策略层与人工审核把关。

07 / PROBABILITY

Probability / Confidence

probabilities 是完整分布；confidence 是把分布压缩成一个 0–1 的摘要。Choice 的 confidence 只看最高概率，Score 还考虑等级距离。

官方明确提醒：confidence 不等于“被选答案正确的概率”。Choice 场景通常应对即将执行的选项的概率设阈值；Noul 直接对 p 设阈值。

校准是群体层面的性质，不保证单个答案正确。上线前必须用自有数据画可靠性图、计算 Brier Score 与 ECE。

08 / AGENTS

Agent Judgment Layer

Tool Routing用 Choice 选择工具，概率不足时不调用。
Model Routing用 Score 判断难度，决定调用轻量模型还是推理模型。
Guardrails用 Noul 检测注入、PII 与越权，再决定是否放行。
